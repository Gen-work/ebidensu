# OPERATOR —— Agent 和操作员说话的方式

> **读者:接手这个仓库、要让操作员在办公 PC 上跑东西的 Agent。**
> 来源:10/26 JJODWDBx 稼働確認(003)的复盘(KNOWLEDGE K-44)和操作员 10/27 的话:
> 「Agent 要有一套接近操作员的说话方法:拉代码的命令、切分支、一组建环境和设对变量、路径的命令——不要留给操作员。
> 要拿到对的需求,就请操作员确认你的解释。先问,再做。」

---

## 1. 操作员只粘贴,不配置

交出去的每一步都是**能整块复制、直接执行**的命令。操作员不需要知道分支、路径、变量从哪里来。

**拉代码**:写全分支名,并说清它在不在 main 里(「main 上还没有,要切到 `claude/xxx`」):

```powershell
cd <仓库在这台 PC 上的路径>      # 不知道就先问,别猜
git fetch origin claude/<slug>
git checkout claude/<slug>
git pull origin claude/<slug>
```

**建环境**:工作文件夹、`$W`、`ebi.local.json` 一次给齐,用命令生成文件(UTF-8 无 BOM),不要说「把下面的 JSON 存成文件」:

```powershell
$W = 'C:\Users\<you>\work-<flow>'
New-Item -ItemType Directory -Force $W | Out-Null
$json = @'
{ "paths": { "<key>": "<value>" } }
'@
[IO.File]::WriteAllText("$W\ebi.local.json", $json, (New-Object Text.UTF8Encoding $false))
```

- 真值(URL、共享盘路径、名字)不进仓库:命令里留 `<...>` 占位,并**逐个写出在哪里看得到**(Edge 地址栏、エクスプローラー的地址栏、哪封邮件)。
- 最后一行永远是**验证环境**的命令(`Tests\Run-Tests.ps1`、`ebi.ps1 profile check <p> -WorkDir $W`、`ebi.ps1 dryrun ...`),并说出「看到什么算对」。
- 一次只给一段;操作员把结果贴回来,再给下一段。

## 2. 先复述,等确认,再动手

- **需求**:先用自己的话复述(读回),写成**能逐条答「对 / 不对」的句子**,等操作员确认后再写代码。沉默、或只回答了其中几条,不等于全部同意。
- **动作**:改操作员的文件、跑会写东西的命令、推送之前,先说「我要做 X,会改 Y」,等一句「好」。
- **读回一屏以内**:只问猜错会整体重做的;其余带默认值写出来,注明「不改就按这个」。

## 3. 操作员的饱和度看不出来

- 开头先问一句现在有多少时间。忙的时候只给一步,或者只要**原始材料**(截图、附件、参考资料),需求由 Agent 自己从材料里读。
- 先交最省人力的那一段;操作员已经手工做完,也是合法的结果(K-44)。
- 回复结论先行,命令放在最前面。

## 4. 交接时写清

分支名、是否已合并、PR 号、下一条该打的命令、还悬着的问题——写在交接卡和回复里的同一个地方。
